# Decisions log

Record of design choices made along the way — including rejected alternatives —
so the reasoning isn't lost when revisiting.

| # | Decision | Reasoning |
|---|---|---|
| 1 | No Calibre application, no Calibre-Web | Dislike Calibre's bloat; Calibre-Web depends on Calibre's runtime and database. No Calibre tools used at runtime. |
| 2 | Filesystem as source of truth, SQLite as derived index | Keeps memory and IO costs low on small hardware — no in-memory index to rebuild on cold start. Plus filesystem-as-truth survives `ebookfs` retirement. |
| 3 | Calibre-style directory layout — structure only | The `Author, Sort/Title (id)/` tree is borrowed from Calibre because it's a familiar, human-browsable convention. It is *not* a drop-in Calibre library: Calibre keeps `metadata.opf` and `cover.jpg` sidecars beside each epub (embedding them only on export/copy) plus a `metadata.db`, whereas ebookfs writes bibliographic data into the epub's internal OPF on every edit (#13) and keeps non-bibliographic extras in `meta.toml`. The actual interop hatch is that every epub is self-describing — any tool, Calibre included, can re-import the files with full bibliographic fidelity; only the `meta.toml` extras (status, rating, custom tags, ids) would need migration. |
| 4 | 9P as the only protocol | Aesthetics and architectural clarity. Keeps the client/server contract minimal and language-agnostic — anything that can mount 9P can drive the library. No HTTP, no gRPC, no custom RPC. |
| 5 | Go, single static binary | Good 9P libraries, clean cross-compile to ARM with `CGO_ENABLED=0`. |
| 6 | USB/rsync-only e-reader sync, no Drive | Avoids Google ecosystem dependency. Keeps every layer owned. The `reader/` view is an rsync source; copying to the device is the client's job. |
| 7 | No Kobo HTTP browser interface | "I'm away and want a book" is a hypothetical problem. Speculative design rejected. |
| 8 | Hand-write both the epub parser and writer | Zip + OPF parsing and surgical OPF XML editing are small, well-defined problems. The writer uses `beevik/etree` for round-trip-safe XML edits (namespace declarations survive) plus an atomic zip rewrite that preserves the `mimetype` entry's STORED compression. Outcome: no Calibre or external tools (e.g. `ebook-meta`) required at runtime — a static binary with zero external tool dependencies, at no more complexity than the subprocess+temp-file pattern shelling out would have required. |
| 9 | `modernc.org/sqlite` over `mattn/go-sqlite3` | Pure Go, no cgo, clean ARM cross-compile. |
| 10 | `knusbaum/go9p` for 9P (forked) | Simpler API for synthetic filesystem construction versus `hugelgupf/p9`. Personal fork at `ramblingenzyme/go9p` (see `go.mod` replace directive and `go9p-fork.md`). |
| 11 | Per-book directory with synthetic files | Plan 9 idiom, makes editing first-class through filesystem ops, `$EDITOR` works for free. |
| 12 | `ctl` file for batch operations | Avoids 100-round-trip patterns over 9P; Plan 9 idiomatic. (Planned — see ROADMAP.) |
| 13 | Epub's internal OPF is canonical for bibliographic metadata; `meta.toml` carries only sidecar extras | One source of truth for bibliographic data. The Kobo and every other reader read OPF from inside the epub, so editing metadata must update the file itself. A sidecar OPF would just duplicate what the epub already contains, and the two would inevitably drift. `meta.toml` carries only what doesn't belong in OPF: internal id, reading status, rating, custom tags. |
| 14 | Id collisions during reindex are fatal, never silently renumber | Duplicate ids almost always indicate user error (restored backup, manual copy). Silent renumbering would break stable external references keyed on the id. Fail loud; the user fixes it manually. |
| 15 | `inbox/` is a synthetic 9P directory, not a real filesystem path | `Tclunk` provides an explicit transaction boundary — no fsnotify, no partial-write races, no `.failed` files lingering on disk. Errors propagate synchronously to the writing client. Drops the fsnotify dependency entirely. |
| 16 | The server host loopback-mounts its own 9P export | Re-enables "drop a file in a directory" workflows for external tools (LazyLibrarian, scripts) without compromising the 9P-only ingestion contract. Local and remote tools share one code path. See `docs/deployment.md`. |
| 17 | Always reindex from the filesystem on every startup | Safety over performance. The index is a derived cache; rebuilding on every start guarantees it never drifts from the authoritative store. At realistic library sizes a full reindex completes in seconds. |
| 18 | Individual field files instead of a combined TOML `metadata` file | More Plan 9-idiomatic (one value per file). Avoids TOML parsing on every write. Each editable field is a few lines of declarative config in the field map. The combined `metadata` file was in the original design but was an unnecessary abstraction layer. |
| 19 | KEPUB conversion for Kobo-format output | Native KEPUB avoids on-device conversion and fixes formatting issues on Kobo devices. Uses `kepubify/v4` with an on-disk cache (per-book locks, mtime-based staleness). The `reader/` view serves either the original epub or the converted kepub. |
| 20 | Logging via `log/slog` | Started on stdlib `log` (small project, structured logging deferred); migrated to `log/slog` once configurable level and text/JSON output were wanted. The migration was mechanical, as predicted. |
| 21 | Array fields (authors, tags) honour open-mode truncation semantics | `fieldFile.Open` honours `OTRUNC`: shell `>` starts the write buffer empty (overwrite), while `>>` or in-place edits seed the buffer with the current value so writing at the end appends. Clients that don't send `OTRUNC` (Linux v9fs on 9P2000) are handled by seeding from the current value. Validation and atomicity still flow through `Edits.Validate` on close. |
